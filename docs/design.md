# en-words 方案设计

> 状态：M1、M2、M3 已完成（2026-11-10）。M4（AI 陪练）是可选项，没有做。使用方法见 [README](../README.md)。

## 1. 目标

使用者：高级全栈工程师，技术栈 React / Vue / Python / Java / Rust / Node.js。

| 目标 | 达标标准 |
|---|---|
| 英文技术面试 | 能连续 2–3 分钟讲清一个项目、一个架构决策或一道系统设计题，不因找词而卡住 |
| 日常同事沟通 | 能参与站会、方案评审、Code Review、1:1、事故复盘和闲聊，听得懂、接得上 |
| 阅读书籍和文献 | 读 DDIA、技术论文、工程博客时，生词率低于 2%，不依赖翻译 |

整体对应 CEFR B2+ 到 C1。周期 6 个月，每天 60–90 分钟。

不做的事：不做通用背单词应用，不做账号和云同步，不做移动端 App。

## 2. 学习方法（工具要落地的规则）

1. **学词块，不学孤立单词**。每条内容都带搭配和例句。
2. **两个方向分开计分**。同一条内容有两份独立的记忆状态：
   - 识别（英 → 中）：服务阅读和听力
   - 产出（中 → 英，开口说）：服务面试和沟通
3. **间隔重复**。用 FSRS 算法安排复习，比固定间隔表更省时间。
4. **从自己的缺口里收词**。口答卡住的表达、阅读遇到的生词，一键进入复习队列。
5. **输出闭环**。每天都要有开口的环节：限时口答并录音，回听后自评。

## 3. 内容体系

### 3.1 四层词库

| 层 | 内容 | 目标量 | 方向 | 来源 |
|---|---|---|---|---|
| A 通用核心 | 日常高频词 | 约 2800 词族 | 识别 + 产出 | NGSL 词表（开放授权），先测评，只学不会的 |
| B 职场沟通 | 会议、协作、书面消息、反馈、闲聊 | 900 条词块 | 产出为主 | 编写 |
| C 技术和面试 | 见 3.2 | 1400 条词块 | 产出为主 | 编写 |
| D 学术书面 | 技术书和论文里的书面词 | 2000 词 | 只练识别 | NAWL 学术词表 + 技术书高频词 |

A 层不逐条学。先做一次 15 分钟的抽样测评，估出已掌握的范围，只把不会的放进队列。

**M3 实现时对 A、D 两层的调整**：没有用 NGSL 和 NAWL 两份词表，改用开源词典 ECDICT（MIT 授权）生成一份词频词典，因为它同时带中文释义、音标、词频排名和词形变化，阅读助手和测评都需要这些。

- 词典包含最常用的 3 万个词（按词频排序），另加约 790 个补充词：内置内容里出现过的低频词，以及带计算机义项的词（如 latency、idempotent）。生成脚本是 `scripts/build-wordlist.mjs`，产物是 `content/wordlists/frequency.json`。
- A、D 两层没有预置内容，只有“生词本”：从测评、分段筛查和阅读里收进来的词。词频排名 3000 以内的归 A 层（认读加中译英），其余归 D 层（只练认读）。
- 这样两层的规模由你实际不会的词决定，不是固定的 2800 和 2000。

## 4. 功能模块

### 4.1 今日任务（首页）

按当天到期量自动排出一份清单：到期复习、新学条目（默认每天 20 条，可调）、一道口答题、一段阅读。显示连续天数和预计用时。

### 4.2 复习

**新学**：每组 5 条同主题词块。逐条听读音、看例句、跟读一遍，5 条看完立刻做一轮中译英小测，答错的当场再测。

**产出方向的四级阶梯**。同一条内容随着记得越来越牢，题目自动变难，不在已经会的题型上浪费时间：

| 级 | 题目 | 要求 | 升级条件 |
|---|---|---|---|
| 1 提示回忆 | 显示中文提示，例如“单点故障” | 5 秒内说出词块 | 记忆稳定度达到 4 天 |
| 2 整句翻译 | 显示中文句子 | 10 秒内开始说出完整英文句子 | 稳定度达到 15 天 |
| 3 情境应答 | 显示一个提问或情境，例如“面试官问：旧架构最大的风险是什么？” | 15 秒内开始，用 1–2 句话回答，用上这个词块 | 最高一级 |
| 4 自由运用 | 不是卡片，是口答题的提示词块 | 在 2 分钟回答里自然用上 | 见 4.4 |

按 FSRS 的默认参数，一路评“记得”时大约每复习一次升一级。评“忘了”后稳定度下降，自动退回低级题型。

**识别方向**：显示英文和例句，回想意思后翻面。D 层只走这个方向。

**听辨**：只播放读音，回想意思后翻面。B 层内容每隔几次复习穿插一次。

**自评标准**（产出方向带 5 秒倒计时）：

| 评分 | 标准 |
|---|---|
| 忘了 | 没说出来，或者说错 |
| 困难 | 说对了，但超过 5 秒或有停顿 |
| 记得 | 5 秒内说对 |
| 很熟 | 脱口而出 |

**省时间的规则**：

- 第一次见到就会的内容，点“已经会了”，跳过 1 级，约 7 天后从整句翻译开始考。
- 说得出就算认得：中译英评为“记得”或“很熟”时，同一条当天到期的认读卡自动按“记得”带过，不再单独出题。
- 本轮评为“忘了”的条目，在队列最后再练一遍，只练不计分，说对为止。
- 目标记忆保持率设为 90%，由 FSRS 计算间隔，不多复习。
- 复习时不同主题混排；新学时同主题成组。
- 同一条累计忘 4 次就暂停，提示改写：在词库里给它写一句关于自己经历的句子，之后整句翻译题优先考这一句。
- 复习限时（默认 25 分钟），到时间就停，剩下的顺延。

快捷键全程可用（空格翻面，1–4 自评）。

### 4.3 词库

按层、分类、掌握程度筛选和搜索。每条显示释义、例句、搭配、语气（正式 / 中性 / 口语）、使用场景和两个方向的掌握状态。可以手动添加、编辑、暂停。

### 4.4 口语练习

1. 抽题（可按分类），显示提示词块。
2. 计时口答并录音（浏览器本地录音，文件留在本机）。
3. 回听，勾选用上了哪些提示词块，自评流利度。
4. 把卡住的表达记成新条目，进入复习队列。
5. 同一题立刻再答一遍，限时缩短到 90 秒。第二遍通常明显更顺，这是流利度提升最快的环节。

另有两个模板：STAR 故事卡（把 5–6 个核心经历写成英文提纲），系统设计讲解框架（需求澄清 → 规模估算 → 接口 → 数据模型 → 架构 → 瓶颈和取舍）。

实现时定下的细节：

- **抽题**：先轮到最久没练的分类，再在分类里选没练过的题，保证各类题都练到。今日页每天推荐一道。
- **提问**：打开题目时自动朗读题目，像面试官提问。中文意思默认收起。
- **提纲**：第一遍答完才显示，用来对照漏了什么。第二遍开始前可以看，作答时收起。
- **录音**：拿不到麦克风或录音失败时照常计时，只是不能回听。录音只保留最近 20 次，备份文件里不含录音。
- **卡住的表达**：先用中文记下来；查到英文说法后填进去，一键建成自己的词条并进入复习（明天开始出题）。提示词块里还没学的，也可以一键加入复习。
- **4 级“自由运用”**：没有做成单独的一级。记得很牢的卡片继续按情境应答出题，口答题的提示词块另外提供在长回答里运用的机会。这样不会因为停卡而遗忘。

### 4.5 场景对话

选场景后逐轮进行：工具朗读同事台词，你口头回应，再对照参考说法。参考说法里的词块可以一键加入复习。

实现时定下的细节：

- 同事的话默认只朗读、不显示原文，听不清再点开，顺便练听力。
- 轮到你时，题面是“你想表达的意思”（中文意图，不是逐字翻译），意思到了就算对。
- 每轮自评“说出来了”或“没说出来”，只用于场景结束时的统计，不进入间隔重复。要长期记住的表达靠“加入复习”。
- 已经说过的对话保留在上方，随时可以重听。

### 4.6 阅读助手

粘贴一段英文（书摘、文档、论文段落）：
- 统计词汇覆盖率，标出不认识的词（对照 A、D 层词表和你的掌握记录）。
- 点词看释义，一键加入生词本，自动带上原句作例句。
- 记录阅读日志：读了什么、覆盖率变化。

实现时定下的细节：

- **怎么判断认不认识**，按优先级：复习里已掌握的算认识；在生词本或复习里的算“学习中”；手动标过的按标记；带计算机义项的补充词默认认识；其余按词频排名，排名在“默认认识前 N 个词”以内的算认识。N 由测评得出，也可以在词汇页手动改，没测评时是 3000。
- **词形还原**：先查词典里的变形表（gave → give），查不到再按词尾规则猜（caches → cache）。一个词既是词条又是别的词的变形时，取词频更高的解释（are 算 be，不算“公亩”）。
- **覆盖率** = 认识的词数 ÷ 词典里查得到的词数。词典里没有的词（专有名词、很新的术语）不计入，单独标出。“学习中”的词不算认识。
- **收词**：点词收进生词本时带上所在的整句作例句。生词列表按出现次数排序，可以一键收入出现 2 次以上的。
- 原文不保存，阅读日志只记标题、词数、覆盖率、生词数和收词数。

### 4.6.1 词汇量测评和分段筛查

- **测评**：按词频每 1000 个词一段，每段随机抽 10 个，从高频到低频。回答“认识”后要看释义确认，可以改口。连续两段认识的不超过 2 个就提前结束，最多测 15 段。词汇量 = 各段认识的比例 × 1000 之和。从最高频开始连续达到 80% 的那几段，决定阅读助手的“默认认识前 N 个词”。
- **分段筛查**：把一段里没筛过的词逐个过一遍，认识的按 2 跳过，不认识的按 1 并自动收进生词本，每批 50 个。这是系统地补 A、D 两层的办法：只学不会的词。

### 4.7 统计

各层和各分类的掌握比例、两个方向的对比、未来 30 天的复习量预测、每日学习时长。

实现时：页面顶部是六个数字（连续天数、已学、已掌握、词汇量估计、练过的面试题、最近一次阅读的认识占比），下面是两张柱状图（未来 30 天到期量、过去 30 天学习时长）和两张表（两个方向、各分类进度）。学习时长只统计复习和口答，新学和场景对话没有计时。今日页的进度表改为只按四层汇总。

### 4.8 数据导入导出

全量导出和导入 JSON（备份、换电脑）。支持从 CSV 批量导入自己的词表。

## 5. 技术方案

### 5.1 选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vite + Vue 3 + TypeScript | 模块较多，需要组件化和类型约束；也可以换成 React，工作量相同 |
| 状态 | Pinia | |
| 存储 | IndexedDB（Dexie） | 数据量上万条加录音文件，localStorage 放不下 |
| 复习算法 | ts-fsrs | FSRS 的开源实现 |
| 发音 | 浏览器 SpeechSynthesis | 免费，离线可用，Edge 自带的英文语音质量足够 |
| 录音 | MediaRecorder | 浏览器自带 |
| 样式 | 自写 CSS，浅色和深色主题 | 界面简单，不需要组件库 |
| 测试 | Vitest | 覆盖调度、导入导出、覆盖率分析这些纯逻辑 |

之前提过“单个 HTML 文件、不用安装”。范围扩大到四层词库、口语、场景、阅读之后，单文件不好维护，所以改为 Vite 项目。日常使用时运行 `npm run dev`，然后打开 http://localhost:5310。

端口固定为 5310，不用 Vite 默认的 5173：学习记录存在 IndexedDB 里，按“地址 + 端口”隔离，端口一变就会看到另一份空数据；而 5173 容易被别的项目占用。

### 5.3 数据模型

```ts
// 内容（只读，来自 content/，启动时同步进数据库）
interface Entry {
  id: string;                 // 例如 "c.arch.eventual-consistency"
  term: string;               // 英文词或词块
  kind: 'word' | 'chunk' | 'sentence';
  layer: 'A' | 'B' | 'C' | 'D';
  topics: string[];           // 例如 ["architecture", "distributed"]
  zh: string;                 // 中文释义或提示
  ipa?: string;
  examples: { en: string; zh: string }[];
  collocations?: string[];
  register?: 'formal' | 'neutral' | 'casual';
  note?: string;              // 用法说明、易错点
  source: 'builtin' | 'user';
}

// 学习状态（每条内容每个方向一份）
interface CardState {
  entryId: string;
  direction: 'recognize' | 'produce';
  due: number;                // 下次复习时间
  stability: number;          // 以下为 FSRS 字段
  difficulty: number;
  reps: number;
  lapses: number;
  state: 'new' | 'learning' | 'review' | 'relearning';
  suspended: boolean;
}

interface ReviewLog { entryId: string; direction: string; rating: 1|2|3|4; at: number; ms: number; }

interface Question {
  id: string; category: string; level: 'mid' | 'senior';
  prompt: string; outline: string[]; chunkIds: string[];
}

interface Scenario {
  id: string; title: string; setting: string;
  turns: { speaker: 'colleague' | 'me'; text: string; chunkIds?: string[] }[];
}

interface SpeakingAttempt {
  id: string; questionId: string; at: number; seconds: number;
  audio?: Blob; usedChunkIds: string[]; fluency: 1|2|3|4|5; gaps: string;
}

interface ReadingLog { id: string; title: string; at: number; words: number; coverage: number; added: string[]; }
```

上面是设计时的草图，实际定义以 `src/types.ts` 为准（例如 `Entry` 多了 `category` 和情境题 `situation`）。

内容和学习状态分开存：内置内容打包进应用、运行时放在内存里，IndexedDB 只存学习状态、复习日志、自己添加的词条和句子、设置。内容更新不影响已有的学习记录。条目 id 由层、分类和英文生成，所以改动已有条目的英文会让它的学习记录对不上。

### 5.4 每日队列规则

1. 先排到期复习，产出方向优先（更难，也更重要）。
2. 新条目每 5 条一组，同组来自同一个分类。每 4 组里 C 层 2 组、B 层 1 组、A 或 D 层 1 组，某层没有内容时由其他层补上；同一层内优先轮到学得最少的分类。每天的总条数在设置里改（默认 20）。
3. 一组学完并通过小测后，两个方向同时建卡：小测一次说对的排到约 3 天后，说错过的排到明天。D 层只建识别卡。
4. 当天总量超过上限（默认 120 张）时，新条目自动减少。
